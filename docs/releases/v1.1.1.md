# v1.1.1 — Wi-Fi 6 开启，驱动加上内核版本上界

发布日期：2026-11-03

## 主要变化

| 项目 | v1.1.0 | v1.1.1 |
| --- | --- | --- |
| `boot-args` | 无 HE 参数 | 追加 `itlwm_he=1` |
| 链路层 | 802.11ac | `802.11 a/b/g/n/ac/ax` |
| `AirportItlwm` 的 `MaxKernel` | 空（无上限） | `25.99.99` |

### 1. 开启 802.11ax（Wi-Fi 6）

`itlwm` 的 HE 实现默认关闭，需要在 boot-args 里显式打开。实测：

```
PHY Mode:      802.11ax
Channel:       40 (5 GHz, 80MHz)
Security:      WPA2 Personal
Transmit Rate: 245 Mbps
MCS Index:     3
Firmware:      itlwm: 2.4.0_7204c69
```

协商速率比 ac 时代的 260 Mbps 略低——这是 `itlwm` 的 HE 实现偏保守，不是故障。要真正吃到 Wi-Fi 6 带宽，还需要路由器开启 160 MHz 频宽、信号足够强。

**如果你的机器出现断连或明显掉速**，删掉 `itlwm_he=1` 重启即可回到 ac。

### 2. `AirportItlwm` 的 `MaxKernel` 封顶

`MaxKernel` 比较的是**内核（Darwin）版本**，不是 macOS 版本号：macOS 26 跑在 Darwin 25 上。

`AirportItlwm` 依赖 OpenCore 的 OCAK 修补 `IO80211Controller` 的 `_RESERVEDIO80211Controller1~16` 保留槽位，前提是父类虚表布局与编译时完全一致——这个前提只在作者对标的系统上成立。不封顶的话，升到 macOS 27（Darwin 26）时这个只为 Tahoe 编译的驱动仍会被注入：轻则 patch 失败、Wi-Fi 消失，重则启动阶段 panic。

封顶后 OpenCore 在注入阶段直接跳过。`25.99.99` 覆盖整个 Darwin 25 系列，又在 Darwin 26 面前精确停住（`SimpleHDA` 官方示例用的正是这一组值）。

> 代价：升级到 macOS 27 后 Wi-Fi 会直接不可用，需要等社区出新构建再手动放开上界。

## 升级注意

1. 三码是占位符，先用 GenSMBIOS 生成自己的 `MacPro7,1` 三码。
2. 从 v1.1.0 升级：覆盖 `EFI` 即可，但**保留你自己的 `PlatformInfo > Generic`**。
3. 本版本不需要重装任何东西，也不改系统卷、不动 NVRAM（除 boot-args 外）。
4. 回滚：换回 v1.1.0 的 EFI，或仅从 boot-args 里删掉 `itlwm_he=1`、把 `MaxKernel` 改回空。
