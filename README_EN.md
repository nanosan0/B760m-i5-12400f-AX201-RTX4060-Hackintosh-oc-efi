## ⚠️ Read this first

**The SMBIOS values in this repository are placeholders. It will not boot as-is.**

```xml
<string>MLB-GOES-HERE</string>
<string>SERIAL-GOES-HERE</string>
<string>UUID-GOES-HERE</string>
<data>AAAAAAAA</data>
```

Use [GenSMBIOS](https://github.com/corpnewt/GenSMBIOS) to generate your own values for the model **MacPro7,1**, then put them into `EFI/OC/config.plist` under `PlatformInfo → Generic`:

| Field | What to put there |
| --- | --- |
| `SystemProductName` | leave as `MacPro7,1` |
| `SystemSerialNumber` | the Serial generated by GenSMBIOS |
| `MLB` | the MLB generated by GenSMBIOS |
| `SystemUUID` | the SmUUID generated by GenSMBIOS |
| `ROM` | your NIC's MAC address (6 bytes); GenSMBIOS generates this for you |

> Why not ship the author's real values: publishing a real set of identifiers lets anyone sign into iMessage / FaceTime with the same identity, which eventually gets the serial blacklisted by Apple. Nobody wins.

## Installation

1. **Prepare a FAT32 USB stick of at least 200 MB** (or use your ESP directly).
2. Copy the whole `EFI/` folder from this repository to the root of the stick, so you end up with `USB/EFI/BOOT/BOOTx64.efi`.
   > Copy the `EFI` level itself — do not end up with `EFI/EFI/BOOT`.
3. **Fill in your own SMBIOS values** (see the warning at the top).
4. BIOS settings:
   - `Secure Boot` → **Disabled**
   - `Fast Boot` → **Disabled**
   - `VT-d` → Disabled (or leave it on and rely on `DisableIoMapper`)
   - `Above 4G Decoding` → **Enabled**
   - `Re-Size BAR Support` → Enabled (works together with `ResizeGpuBars`)
   - `CFG-Lock` → Disabled (if the option does not exist, `AppleXcpmCfgLock` is already enabled as a fallback)
   - `SATA Mode` → AHCI
5. Boot from the stick and go into the macOS installer.

## Configuration notes: why it is written this way

### 1. `SecureBootModel = Disabled` and `FixupAppleEfiImages`

These two go together. You need both.

What the official `Configuration.tex` says about `FixupAppleEfiImages`:

> On a system with such a modern, stricter loader this quirk is required to load Mac OS X 10.4 to macOS 10.12, and **is required for all newer macOS when `SecureBootModel` is set to `Disabled`**.

macOS's `boot.efi` carries a `W^X` permission bug that strict PE loaders refuse to load. This configuration needs `SecureBootModel = Disabled` in order to use the OCLP-Mod root patch, so `FixupAppleEfiImages` **must** be `true`.

> Plenty of EFIs downloaded from elsewhere are missing this key (`ocvalidate` reports `Missing key`). Its failsafe value is `false`, so a missing key is the same as having it off — it boots fine most of the time and hangs the moment you hit a strict firmware.

### 2. Graphics: NullMoth NVIDIA driver

NVIDIA does not provide drivers for recent macOS releases (the Web Driver era is long over). This machine uses  
**[nullmoth/nvidia-macos-driver](https://github.com/nullmoth/nvidia-macos-driver)** — a third-party Metal driver that translates Apple Metal commands into Vulkan at runtime.

```
Metal App → NVMTLDriver.bundle → translator (AIR → SPIR-V) → NVK (Mesa Vulkan) → NVRM / NVAccel / NVRMFB → GPU
```

| Component | Installed to | Role |
| --- | --- | --- |
| `NVMTLDriver.bundle` | `/Library/GPUBundles/` | the Metal driver plug-in |
| `libnvmtl_translate.dylib` | inside the plug-in | shader translation (based on metal2vulkan, LGPL-3.0) |
| `nvk/` | `/Library/GPUBundles/nvmtl/` | Vulkan backend (Mesa + NAK compiler) |
| `NVRM` `NVAccel` `NVRMFB` `NVRMAGDC` | `/Library/Extensions/` | kernel extensions: driver core / accelerator / display framebuffer / display policy shim |
| GSP firmware | `/Users/Shared/nvfw/nvidia/…` | vendor firmware from NVIDIA |

**Supported range**: Turing and newer — GTX 16 series, RTX 20 / 30 / 40 / 50, TITAN RTX, Quadro RTX, T series.  
**This machine has an Ada-based RTX 4060**, which is covered by the official device table. The author tests mainly on an RTX 5060, so other models may have undiscovered issues.

> **Key point: never inject these kexts through `EFI/OC/Kexts`.**  
> They load from the Auxiliary Kernel Collection; OpenCore's only job is to set SIP and boot-args.  
> That is why this repository's `config.plist` contains **no NVIDIA-related entries at all** — that is correct, not a missing configuration.

#### What the driver requires from OpenCore (checked item by item here)

| Requirement | This configuration | Result |
| --- | --- | --- |
| boot-args contain `nvfb=1 nvaccel=1 nvfbheads=4 -nvkmsnosmooth amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0` | all present | ✅ |
| No `nv_disable=1`, no `-wegnoegpu` (both hide the NVIDIA card) | neither present | ✅ |
| `csr-active-config` includes the `0x0A43` bits | `0x0FFF` (superset, includes them) | ✅ |
| `Misc > Security > SecureBootModel` = `Disabled` | Disabled | ✅ |
| `Lilu.kext` and `AMFIPass.kext` in `Kernel > Add` and enabled | both present | ✅ |
| `Kernel > Block` blocks `com.apple.iokit.IONDRVSupport` | blocked | ✅ |
| No WhateverGreen NVIDIA patch for this card, no `agdpmod=pikera` | neither present | ✅ |
| Keys written to NVRAM must also be listed in `NVRAM > Delete` | `boot-args`, `csr-active-config` both listed | ✅ |
| The model must be accepted by this macOS version | `MacPro7,1` — 1401 has picked it for desktops with a dGPU since 1.14; accepted by both macOS 15 and 26 (`iMacPro1,1` is rejected by macOS 26) | ✅ |
| BIOS: Above 4G Decoding ON, CSM OFF | see step 4 of "Installation" above | — |

**Why `SecureBootModel` must be `Disabled`**: Apple Secure Boot refuses kexts that Apple has not signed, and the NVRM family loads unsigned.  
This is also why `FixupAppleEfiImages` in §1 is **mandatory** here — the two are upstream and downstream of the same causal chain.

#### Installing

Use the author's **1401** app ([nullmoth/1401](https://github.com/nullmoth/1401)). It locates the OpenCore partition you boot from, backs up `config.plist`, writes the settings above, installs the driver, and adds a **1401: Remove NVIDIA driver** entry to the boot menu for one-click rollback.

Installing manually means running `install.sh`, rebuilding the Auxiliary Kernel Collection, and getting the OpenCore configuration right by hand — get the order wrong and you get a black screen.

> On the first boot with the driver, it can sit at `PCI configuration end` for up to about a minute while the GPU comes up. That is normal; do not assume it has hung.

#### What `gfxrst=4` actually does

**It is not a GPU reset.** Per the official documentation: when WhateverGreen is installed, its boot-screen copy reads already-freed memory when the NVIDIA display is switched on, which panics. `gfxrst=4` suppresses that conflict.  
So it has nothing to do with the GPU and everything to do with **WhateverGreen** — this machine keeps WEG for the Intel platform, so the flag is needed.

#### Troubleshooting boot-args (do not add these normally)

| Flag | What it does |
| --- | --- |
| `-nvrmnoflip` | disables zero-copy scanout; first thing to try for desktop flicker or tearing while moving the cursor |
| `-nvrmnopm` | disables system sleep support; the symptom is "the GPU never comes back after sleep" |
| `-nvrmnogo` | the driver does not start on its own; wait for a manual `nvrmctl go` |
| `-nvrmnobootscreen` | does not capture the boot screen |

### 3. The three `Kernel > Block` entries

| Blocked kext | Why |
| --- | --- |
| `com.apple.iokit.IOSkywalkFamily` | replaced by the patched build in this repo; without the block the stock version loads first and the Intel NIC never comes up |
| `com.apple.driver.AppleEthernetRL` | the stock RTL driver conflicts with `RTL812xLucy` on this machine |
| `com.apple.iokit.IONDRVSupport` | without the block, the firmware's own framebuffer takes display index 0 away from `NVRMFB` and the NVIDIA output never lights up |

### 4. The three-stage Wi-Fi dependency

On macOS 14+ an Intel card is **not** just a matter of dropping in `AirportItlwm`:

```
IOSkywalkFamily.kext            ← base of the NIC protocol stack (Apple original, needs blocking the stock kext)
IO80211FamilyLegacy.kext        ← the older 802.11 framework
└── AirPortBrcmNIC.kext         ← its plug-in; "Brcm" in the name, but Intel cards mount through it too
AirportItlwm-Ventura.kext       ← the actual Intel driver (Ventura build)
```

> These three Apple originals are not "Broadcom-only, pointless on an Intel machine". Anyone saying so has it wrong.
>
> Why the **Ventura build** of AirportItlwm: the community approach on Tahoe is the Ventura build plus the OCLP-Mod root patch; the Sequoia build does not work on Tahoe.

### 5. boot-args, one by one

```
keepsyms=1 amfi_get_out_of_my_way=0x1 amfi=0x80 ipc_control_port_options=0
nvfb=1 nvaccel=1 nvfbheads=4 -nvkmsnosmooth -lilubetaall gfxrst=4
```

| Flag | What it does |
| --- | --- |
| `keepsyms=1` | keeps function symbols in kernel panics; without it panic logs are bare addresses. **Do not remove** |
| `amfi_get_out_of_my_way=0x1` `amfi=0x80` | disables AMFI validation, together with `AMFIPass` + the root patch |
| `ipc_control_port_options=0` | fixes XPC communication for some apps |
| `nvfb=1` `nvaccel=1` `nvfbheads=4` | required by the NullMoth driver: enable framebuffer, enable NVAccel acceleration, 4 display heads |
| `-nvkmsnosmooth` | also required by the driver: disables nvkms smooth scaling |
| `-lilubetaall` | lets Lilu and its plug-ins load on newer OS versions |
| `gfxrst=4` | required with WhateverGreen: otherwise WEG's boot-screen copy reads freed memory when the NVIDIA display comes up, straight to a panic |

### 6. Logging is off

`Misc > Debug > Target` is set to **0**. Per the official definition, bit `0x01` is the master switch; with it off "all log is discarded" and no `opencore-*.txt` appears in the ESP root. `AppleDebug`, `ApplePanic` and `DisableWatchDog` are also `false`.

When you need logs for troubleshooting:

```xml
<key>Target</key><integer>67</integer>
<key>AppleDebug</key><true/>
<key>ApplePanic</key><true/>
```

Then add `debug=0x100` back at the front of boot-args.

### 7. Other important keys

| Key | Value | Note |
| --- | --- | --- |
| `Misc > Security > ScanPolicy` | `0` | do not restrict scanning; boot from any partition |
| `Misc > Security > Vault` | `Optional` | no vault validation |
| `csr-active-config` | `0x0FFF` | SIP essentially off, needed by the root patch |
| `DeviceProperties` | `layout-id = 77` | a working layout for ALC897 |

## Known limitations

- **The GPU driver is a third-party reverse-engineering effort.** Its kexts live in `/Library/Extensions` and load from the Auxiliary Kernel Collection; every macOS major release may require waiting for the driver to catch up. Before upgrading, check the [releases](https://github.com/nullmoth/nvidia-macos-driver/releases) and `CHANGELOG`.
- **Only Turing and newer GPUs are supported.** Older cards such as Pascal and Maxwell are out of scope.
- **Wi-Fi needs the root patch.** Same story: once `AirportItlwm` is installed to `/Library/Extensions` it depends on the OCLP-Mod patch chain.
- **The `i5-12400F` has no iGPU**, so Sidecar hardware encoding is unavailable, and there is no GUI at all without the dGPU.
- **Porting to another motherboard is not guaranteed.** `SSDT-RTCAWAC` and `SSDT-SBUS` in the ACPI folder were generated for this board specifically; regenerate them for a different one.
- **Back up your EFI before any macOS major upgrade**, and confirm the kexts have caught up.

## Common installation problems

> The first rule is always: **use the latest 1401 and the latest driver**. Many of the problems below were fixed in later versions, and a USB stick made with an older 1401 keeps its old problems until you rebuild it.

### A. Stuck in the picker / cannot reach macOS yet

| Symptom | Cause | What to do |
| --- | --- | --- |
| Hangs at `PCI configuration` | usually Resizable BAR or Above 4G Decoding settings | Enable Above 4G Decoding and disable CSM in BIOS. If it still hangs, export the stick's log |
| `EB.MM.AKM`, `STOP 0x16`, `StartImage failed - Aborted`, `Couldn't allocate runtime area` | the firmware memory map leaves no room for `boot.efi` (common on Ryzen 7000/9000) | rebuild the stick with the latest 1401 — it applies the right memory settings and falls through a list of them automatically. Rebooting the old stick will not help |
| Hangs at `EXITBS:START` | macOS has taken over from the firmware but stops before printing anything. On Intel 12th gen and newer, and on AMD laptops, usually a CPU core layout or memory map problem | start with the latest 1401; then export the stick's `opencore-*.txt`; if there is a panic, photograph the whole screen in verbose mode |
| `This version of Mac OS X is not supported on this platform!` followed by `Mac-…` codes | the configured model is not accepted by this macOS version. **macOS 26 rejects `iMacPro1,1`**; macOS 15 rejects a batch of older models | use `MacPro7,1` — 1401 has picked it for desktops with a dGPU since 1.14, and both macOS 15 and 26 accept it. **This repository ships `MacPro7,1`** |
| The installer freezes completely at around 19 minutes (even Caps Lock is dead), Ryzen 7000/8000/9000 | these boards hang while the installer writes firmware settings | rebuild the stick (fixed in 1.14). If you maintain your own EFI, set `Booter > Quirks > DisableVariableWrite = true` |

| Occasionally hangs after picking the stick, then works when rebuilt | the stick or port is too slow / unstable while reading that ~900 MB recovery image | use a rear USB port, or a different stick |

### B. Display problems after the driver is installed

| Symptom | Cause | What to do |
| --- | --- | --- |
| Desktop looks fine for about a minute, then goes black with only the cursor | about a minute after boot the driver switches to "scan out directly from VRAM" (`NVAccel::autoGo`). If the desktop is actually drawn on the iGPU, or the card's BAR is only a small 256 MB window, that surface is blank | fixed in 1.14 (the driver keeps the copy path on such machines). | Completely black desktop on macOS 26 (Tahoe) | the accelerator (NVAccel) bundled for macOS 26 was outdated | fixed in 1.14 |
| No picture after switching the monitor to another input and back | the driver only lights up "displays it has not seen before" | fixed in 1.14. On older versions unplug and replug the cable |
| Black screen after ~100 seconds on older Intel boards without Resizable BAR, log says `cannot hold … not placing` | the firmware does not list a 64-bit PCI address range, so there is nowhere to put the card's VRAM window | fixed in 1.14 |

| After wake the desktop is black with only the cursor, or stuck on the pre-sleep frame | WindowServer was not told the framebuffer woke up, or its VRAM was replaced | fixed in newer builds. If it still happens, send logs — they contain `NVRM-xnu: wake #` and `NVRM-fb: system wake` |

### C. How to roll back when something breaks (the most important section)

A bad driver can leave you with no picture at all. **Remember these three escape routes**, in order of severity:

**1. Skip the driver for this one boot**

In the OpenCore picker choose **`1401: Start once without NVIDIA driver`**, press `Y`, then pick macOS or Recovery. The next boot restores the driver automatically.

**2. Remove the driver completely**

Choose **`1401: Remove NVIDIA driver`**, press `Y`, then pick macOS. It uninstalls and reboots by itself, and resets the saved resolution and refresh rate to safe defaults — so even if you had set a mode the display cannot show, you still get a picture.

**3. You cannot even see the picker**

Boot into macOS Recovery (the driver does not run there), open Terminal and run:

```bash
nvram 7C436110-AB2A-4BBB-A880-FE41995C9F82:nullmoth-remove=1
```

Then reboot into macOS. The machine removes the driver itself and reboots once more, **with no display needed at any point**. The effect is identical to the uninstall entry in the picker.

#### Cannot find those two 1401 entries in the picker?

Per the official documentation, the installer switches the picker to **`Builtin`** and stops hiding the entries behind the space bar.

This repository's `Misc > Boot` currently is:

- `HideAuxiliary = false` ✅ entries do not require pressing space
- `PickerMode = External` (OpenCanopy graphical picker) ⚠️ differs from the official default of `Builtin`

**If your display is broken and you cannot find those two entries, you are in a bad spot.** In that case temporarily change `PickerMode` to `Builtin` so you can see and select them, then change it back to `External` afterwards. This is the only place this repository deviates from the official default configuration.

> Also note: early versions added a `NullMothLogo.efi` boot entry to OpenCore; that is deprecated, and newer installers/updaters/uninstallers remove its entry and file automatically. **If your picker never appears** while that entry is still in the EFI, disable it. This repository contains no `NullMothLogo.efi` entry at all.

### D. Verify whether the driver actually loaded

After rebooting run these two commands:

```bash
kmutil showloaded --list-only | grep nullmoth
system_profiler SPDisplaysDataType | head -20
```

The first should print **4 lines**, for the `NVRM` / `NVAccel` / `NVRMFB` / `NVRMAGDC` kexts.  
The second should show your GeForce card with **Metal: supported**.

Only half of that (kexts loaded but no Metal) usually means `NVAccel` was not correctly built or installed for that macOS version.

### E. Getting logs

When the tables above do not cover it, do not guess:

- **On the Mac**: 1401 → Crash report → **Send logs**
- **1401 on Windows**: **Scan for logs and send them**

It collects driver state (PCI device IDs, BAR addresses), kernel logs, plug-in logs, crash reports and the OpenCore boot log, strips machine names, serial numbers and memory addresses, and gives you a report ID. Paste that report ID into an issue — far more useful than a photo of the screen.

### F. After upgrading from macOS 15 to 26, FileVault appears at boot and even the correct password is rejected

**Symptom**: after the upgrade, a password window (FileVault) appears before macOS starts. Entering the correct account password reports a wrong password, and repeated attempts do not help.

**Cause**: the macOS 26 upgrade turns FileVault back on. Once enabled, unlocking happens in the pre-boot environment **before the kernel loads** — that screen is drawn by Apple's own code; OpenCore only hands over two things: the APFS driver and keyboard events. So the password check is entirely Apple's, and if the APFS driver does not understand the volume's encryption metadata version, the check fails and looks exactly like "wrong password".

The original configuration relied on `UEFI > APFS > EnableJumpstart`, which **automatically extracts** the embedded signed driver from the APFS container. After an upgrade the container may hold both an old and a new Preboot; if the old driver gets picked, it cannot read the new volume's encryption metadata.

**Fix** (included since v1.0.1):

| Item | Value |
| --- | --- |
| `OC/Drivers/apfs_aligned.efi` | added, 718,340 bytes, `sha256 1663fa54…` |
| `UEFI > APFS > EnableJumpstart` | `true` → **`false`** |
| `UEFI > Drivers` | new `apfs_aligned.efi` entry, `Enabled=true`, `LoadEarly=false` |

With Jumpstart off, the APFS driver comes from a fixed file, so there is no more randomness about which version gets picked. The official documentation describes the key as *Load embedded APFS drivers from APFS containers* — given an explicit driver, it is redundant.

> `MinVersion` / `MinDate` only apply to drivers loaded by Jumpstart, so both keys stop having any effect once it is off.

**Check one thing on the first boot after the change**: your macOS volume is still in the OpenCore picker. If the volume is simply gone, the driver failed to load — roll back per section C immediately.

**If the driver is fine and the password still does not work**, the problem is the volume's encryption state. Boot into Recovery (the Recovery partition is not protected by FileVault, so no password is needed) and open Terminal:

```bash
diskutil apfs list                    # check Locked state, confirm there is no leftover volume from the upgrade
diskutil apfs unlockVolume diskXsY    # interactive passphrase prompt; errors are clearer than the GUI
diskutil apfs updatePreboot diskXsY   # run right after a successful unlock to rebuild Preboot
```

**Once you can boot into macOS**, if you do not need FileVault, turn it off in System Settings → Privacy & Security → FileVault so the next major upgrade does not hit this again. Back up your data before turning it off.
